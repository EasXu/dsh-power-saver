<h1 align="center">dsh-power-saver</h1>

<p align="center">
  所有 DSH 项目跑完后，自动关机、休眠或锁定这台电脑。<br>
  <sub>Shut down, hibernate, or lock this PC once every DSH project has finished.</sub><br>
  <a href="https://github.com/EasXu/dsh-power-saver/issues">问题反馈</a> ·
  <a href="LICENSE">MIT 许可</a>
</p>

一个 [DeepSeek Harness (DSH)](https://github.com/deepseek-ai) 插件：监听所有 DSH 会话与后台任务，在所有工作都结束并空闲一段时间后，显示可以取消的倒计时，然后执行一次电源操作——**关机**、**休眠**、**锁定屏幕**，或者**只提示不执行**（安全的试运行）。

入口就在左侧边栏底部、设置按钮旁边的「**自动关机**」。点开即可配置；倒计时开始后，剩余时间会直接显示在这一行里。

## 为什么

长时间的任务经常在睡前或离开时运行。你不想一直盯着屏幕，也不想让电脑整夜开着。dsh-power-saver 把「所有会话都结束了」变成一个安全、可取消的电源操作。

## 功能

- **就在左侧边栏** —— 一个 `sidebar.footer.action` 入口，点开是锚定在侧边栏上方的设置面板，不用再去设置页里找。
- **先看到工作才武装** —— 只有观察到 DSH 会话或后台任务真的运行过，才会开始计时；单纯打开开关不会关掉一台什么都没跑的电脑。
- **所有项目一起判断** —— 任何一个会话、子代理、工作流子任务或后台任务还在运行，计时都会继续等。
- **可取消的倒计时** —— 可配置缓冲时间；侧边栏显示 `mm:ss`，面板里显示大号倒计时，两处都能取消；开始新的 DSH 工作也会自动取消。
- **生效时段** —— 可选的开始/结束时间（例如 `22:00–05:00`，支持跨零点）。时段外完全不做检测和计时；只有时段内新开始的项目才计入，时段结束时倒计时会被取消。
- **安全默认值** —— 功能默认关闭；启用「关机 / 休眠」前会弹出确认并写明完整计划；「试运行」可以完整走一遍流程但不碰系统。
- **失败有原因** —— 例如系统未启用休眠时，面板会显示系统返回的错误，而不是悄悄失败。
- **只在本机** —— 不联网、无遥测。状态只走本机 loopback 的 `/api/power-saver/*`，并经过与 DSH 自身 API 相同的本机信任检查；设置保存在 `$DSH_HOME/power-saver.json`。

## 要求

- 带 `sidebar.footer.action` 槽位的 DSH 版本（当前 Desktop 与 Web 构建）。
- 主要面向 Windows 10/11；macOS 和 Linux 使用尽力而为的系统命令：
  - Windows：`shutdown.exe /s`、`shutdown.exe /h`、`rundll32 user32.dll,LockWorkStation`
  - macOS：`osascript`、`pmset`
  - Linux：`systemctl`、`loginctl`
- Windows 休眠需要系统已启用（管理员终端运行 `powercfg /hibernate on`）。
- 运行时不需要 Node.js，插件零依赖。

## 安装

```sh
git clone https://github.com/EasXu/dsh-power-saver.git
```

然后在 DSH 里：

1. 打开左侧的 **插件** → **添加插件** → **本地目录**，选择克隆下来的 `dsh-power-saver` 目录。
2. 确认插件 bundle 已启用。
3. 打开左侧边栏底部的「**自动关机**」。

也可以让 DSH 里的 agent 用绝对路径执行 `plugin_manager install_bundle` 安装。本地目录安装是链接方式，`git pull` 后重启 DSH 即可更新。

## 使用

1. 点侧边栏底部的「自动关机」。面板会显示当前状态，下面的设置项就是当前生效的计划。
2. 打开「启用」开关。如果动作是「关机」或「休眠」，会先弹出确认，写明将执行的计划；「锁定屏幕」或「仅提示」则直接启用。
3. 设置参数：

| 参数 | 默认 | 含义 |
|---|---|---|
| 触发动作 | 关机 | 关机 / 休眠 / 锁定屏幕 / 仅提示（不执行系统操作） |
| 空闲等待 | 10 分钟 | 所有项目结束后，再观察多久才认为「真的结束了」。0 表示立即开始倒计时（0–720 分钟） |
| 执行倒计时 | 60 秒 | 真正执行前的缓冲时间，期间可以取消。0 表示不等待（0–1800 秒） |
| 生效时段 | 留空 | 两个都留空表示全天生效；填写时必须两个都填。跨零点时让开始晚于结束，例如 `22:00–05:00`。只在时段内检测和计时 |
| 统计后台任务 | 开 | DSH 后台任务也算「项目未结束」，避免任务被中断 |

4. 点「保存设置」。开关会立即保存，并一并保存面板里尚未保存的改动。
5. 点「试运行」可以完整走一遍倒计时和取消，不执行任何系统操作。

### 倒计时与取消

- 倒计时开始后，侧边栏那一行会变成剩余时间 `mm:ss`。
- 点开该行，可以看到大号倒计时、将执行的动作和「取消」。
- 侧边栏收成窄条或被隐藏时，右下角会出现一个小倒计时兜底提示。
- 向任意会话发送消息（有新工作开始运行）会自动取消计划。
- 退出 DSH、停用插件或卸载 bundle 也会取消。

### 生效时段的行为

设置生效时段后，它是一条硬边界，而不是最后才检查一次：

- 时段外不检测、不计时、不武装、不执行。
- 时段开始前就已经在运行的项目**不会**计入，即使它在时段内结束。只有观察到在时段内新开始的项目才会武装调度器。
- 时段结束时，已武装的计划或正在进行的倒计时会被取消，不会在时段外执行。
- 两个时间必须同时填写，或都留空表示全天。跨零点写成开始晚于结束，例如 `22:00–05:00`。

### 倒计时结束后

1. 先把仍在运行的会话日志刷盘（最多 3 秒）。
2. 执行倒计时开始时捕获的动作。倒计时期间修改动作会取消该倒计时，不会悄悄换成另一个动作。
3. 面板显示执行结果；失败时显示系统返回的原因。

## 工作原理

- Host 半边运行在 DSH 进程里：监听 `agent/status`、`agent/disposed`，每秒用 `agents.list()` 交叉核对，并按需统计 `jobs.list()` 中运行中的后台任务。
- 只有在插件已启用、处于生效时段内，并且观察到一次新的运行开始时，才会武装调度器。最后一次活动结束后开始空闲计时；空闲满且仍在时段内时进入倒计时。
- 浏览器半边是纯 CommonJS 客户端模块：一个 `sidebar.footer.action` 入口，加一个 `shell.overlay` 兜底提示。状态通过 `/api/power-saver/status` 读取，写入只经过 `/config`、`/cancel`、`/test`。
- 设置文件以原子方式写入 `$DSH_HOME/power-saver.json`。

## 限制

- 只统计 DSH 会话和 DSH 后台任务；DSH 之外的编译、脚本、终端不会被检测到。
- 计划只存在于 DSH 进程内：退出 DSH 即取消，没有操作系统级的持久任务。
- 关机会强制关闭其他程序，包括其中未保存的工作。
- 休眠需要系统已启用；macOS 上「休眠」对应 `pmset sleepnow`，「锁定」对应显示器睡眠，因为这是最接近的原生命令。
- 生效时段外不检测、不计时。时段开始时已经在运行的项目不会计入；时段结束时正在进行的倒计时会被取消。
- 插件启用或 DSH 启动时已经在运行的项目不计入，除非它在时段内开始了新的回合。

## 开发

无依赖、无构建步骤。

```sh
node --check index.js
node --check client.js
npm test
```

目录：

```
index.js              Host 半边：监听、状态机、HTTP 路由、信任检查
client.js             浏览器半边：侧边栏入口、面板、倒计时界面
cordis.patch.yml      Bundle patch，插入插件行
package.json          Bundle 清单（dsh.bundle + dsh.client）
locale/{en,zh}.json   插件管理里的标题与描述
test/engine.test.mjs  Host 状态机的纯 Node 测试
icon.svg              原始插件图标
```

Host 状态机通过 `__test` 导出，可以用假时钟和假服务测试，见 `test/engine.test.mjs`。

## 隐私

不发起网络请求，无分析上报。配置只保存在 `$DSH_HOME/power-saver.json`，界面只与本机 Host 通信。
